# Phase 0 Specifications

Specifications define current executable behavior.

Unlike ADRs, specs are mutable: when intended behavior changes, update the spec.

Each non-trivial feature spec should contain:

1. Purpose
2. Scope
3. Preconditions
4. Inputs / Outputs
5. Behavioral Requirements
6. Failure / Edge Cases
7. Provenance Requirements
8. Acceptance Tests
9. Security / Safety Invariants where relevant

Implementation is not complete until the acceptance criteria are covered by tests.
