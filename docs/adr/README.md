# Architecture Decision Records

This directory contains Architecture Decision Records (ADRs) for Telaio.

## Status values

- `Proposed`
- `Accepted`
- `Superseded`
- `Deprecated`
- `Rejected`

ADRs are historical records. Once accepted, do not rewrite the original decision to match later architecture. If the decision changes, add a new ADR and mark the previous one as superseded.

## When to create an ADR

Create an ADR when a change introduces or reverses a meaningful architectural decision, such as:

- responsibility boundaries;
- security or trust boundaries;
- technology/platform choices;
- persistent data models;
- execution/transaction semantics;
- backend abstraction strategy;
- provenance or audit guarantees.

Do not create ADRs for routine implementation details or trivial refactors.
